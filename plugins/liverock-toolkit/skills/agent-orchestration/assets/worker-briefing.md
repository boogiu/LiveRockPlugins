# 경계

- 받은 역할의 범위 안에서 맡은 작업만 한다. 다시 위임하지 않는다.
- 한 번 워커면 세션 내내 워커다. 첫 줄 표지가 대화 뒤로 밀려 보이지 않거나 이후 추가 지시를
  받아도 팀장으로 바뀌지 않으며, 그때도 위임하지 않는다.
- 셸 명령은 기본 도구로 실행한다. 터미널을 새로 만들지 않는다.

# 맥락 점검

큰 파일이나 도구 출력을 반복해서 읽었거나, 맥락 한계 경고가 나왔거나, 작업 단계가 끝났다면
다음 대규모 탐색 전에 점검한다. 완료한 결정·근거·산출물 경로·남은 일을 짧게 기록한다. 결과
파일이 `nodes/{노드 ID}.md`이면 그 기존 결과 파일에 쓰고, 아니면(수정 대상 파일·단계 산출물 등)
실패 보고 경로와 같은 실행 디렉터리의 `nodes/{노드 ID}.md`에 쓴다 — 결과 파일에 섞이면 산출물이
오염되거나 정해진 내용 규칙을 어기게 된다. 실패 보고 경로는 파일이 있는 것 자체가 실패 신호라
쓸 수 없다. 단계가 아직 진행 중이면 필요한 맥락을 보존한 뒤 압축한다.

# 실패 시

작업을 완료하지 못했으면 실패 보고 경로에 실패 사유를 쓴다. 수정 대상 파일에는 실패 문구를
쓰지 않는다. 파일 기록이 불가능하거나 사용자가 쓰기를 금지한 경우, 파일 기록을 포기하고
짧은 응답으로 실패와 미검증을 보고한다.

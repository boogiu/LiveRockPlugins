# 연구 작업 오케스트레이션

## 맡는 것과 맡지 않는 것

**이 스킬은 혼자 돌지 않는다.** 워커를 실제로 띄우는 것은 Paseo이고 그 절차는
`agent-orchestration`이 가지고 있다. 이 스킬은 그쪽에 넘길 값을 정할 뿐이다. 둘 중 하나라도
없는 환경에서는 1~5절의 판단은 나오지만 실행할 수단이 없으므로, **판단만 내놓고 실행된
것처럼 보고하지 않는다.** 없는 것이 무엇인지 사용자에게 알리고 멈춘다.

이 스킬은 오케스트레이션 절차를 다시 정의하지 않는다. 같은 절차를 두 벌 두면 어느 쪽을
따를지 매번 갈리고, 둘이 어긋나기 시작하면 고칠 곳이 두 군데가 된다.

| 축 | 담당 |
| --- | --- |
| 워커 기동, 활성·대기 큐, 재시도, 실행 기록, 보고 서식 | `agent-orchestration` |
| 이번 실행에 쿼터를 얼마나 쓸지 | 이 스킬 (1절) |
| 연구 작업을 어떤 단위로 쪼갤지 | 이 스킬 (2절) |
| 프로바이더가 codex 하나뿐일 때 역할에 무엇을 배정할지 | 이 스킬 (3절) |
| 결과가 연구 산출물로서 맞는지 가릴 기준 | 이 스킬 (4·5절) |

`agent-orchestration`이 먼저 돌고, 그 절차 안의 세 지점에서 이 스킬이 값을 공급한다 —
큐 상한을 정할 때(1절), 작업을 쪼갤 때(2절), 워커 브리핑의 합격 기준 칸을 채울 때(4절).

## 1. 쿼터 예산을 먼저 정한다

**기동 전에 이번 실행에 띄울 워커 수를 정하고 사용자에게 알린다.**

쿼터가 넉넉한 환경에서는 워커를 더 띄우는 것이 거의 항상 이득이라 예산을 정할 이유가
없다. 제한 플랜은 반대다. 쿼터가 실행 도중에 마르면 **이미 띄운 워커의 결과까지 못 받는다** —
남은 작업만 못 하는 것이 아니라 그때까지 쓴 것이 통째로 버려진다. 그래서 다 쓰고 나서
줄이는 것이 아니라 시작 전에 정한다.

### 기본값

| 값 | 기본 | 근거 |
| --- | --- | --- |
| 동시 실행 | 2 | 하나가 막혔을 때 놀지 않을 최소치 |
| 이번 실행 총 워커 수 | 5 | 넘어가면 사용자에게 먼저 알리고 답을 받는다 |

이 둘은 출발점이지 상한이 아니다. 실제 플랜의 한도는 조회로 확인되지 않으므로, 사용자가
다른 값을 말하면 그 값을 쓰고 기본값을 근거로 되돌리지 않는다.

### 총 워커 수를 넘길 때

넘겨야 할 것 같으면 기동을 멈추고 무엇을 줄일지 사용자에게 묻는다. 고를 수 있는 것은 셋이다.

| 선택 | 결과 |
| --- | --- |
| 작업을 합친다 | 워커 수가 줄고 워커 하나의 부담이 는다 |
| 일부를 다음으로 미룬다 | 이번 실행 범위가 줄어든다 |
| 예산을 늘린다 | 사용자가 쿼터 소모를 받아들인다 |

**임의로 작업을 빼고 진행하지 않는다.** 뺀 작업은 사용자가 요청한 것이고, 빼는 판단은
사용자 것이다.

### 워커를 안 띄우는 것이 이득일 때

쿼터를 아끼는 가장 확실한 방법은 띄우지 않는 것이다. 아래는 직접 하는 편이 싸다.

- 파일 하나를 읽고 한 값을 꺼내는 일 — 브리핑을 쓰는 비용이 작업보다 크다
- 결과를 받아도 다시 검토해야 하는 일 — 워커 하나에 검토 워커 하나가 더 붙는다
- 앞 작업 결과가 있어야 시작할 수 있는데 그 앞 작업이 아직인 일 — 띄워도 대기만 한다

## 2. 연구 작업을 쪼개는 단위

**병렬로 쪼갤 수 있는지는 "결과가 서로를 필요로 하는가"로 가른다.** 필요로 하면 순차고,
아니면 병렬이다. 작업량이 많다는 것은 쪼갤 근거가 아니다 — 서로 물린 일을 억지로 나누면
워커들이 같은 전제를 각자 다르게 잡고 합쳐지지 않는 결과를 낸다.

| 작업 유형 | 쪼개는 단위 | 병렬 |
| --- | --- | --- |
| 문헌·자료 조사 | 주제 하나 또는 출처 묶음 하나 | 가능 |
| 물성·데이터 수집 | 물질 하나 또는 조건 구간 하나 | 가능 |
| 데이터 정리·변환 | 원본 파일 하나 | 가능 |
| 계산·모델링 | 조건 세트 하나 | 가능 |
| 조건 비교·민감도 | 비교 축 하나 | 가능 |
| 결과 해석 | 쪼개지 않는다 | 불가 |
| 초안 작성 | 쪼개지 않는다 | 불가 |

해석과 작성을 쪼개지 않는 이유는 같다. 둘 다 **전체를 한 번에 봐야 나오는 결론**이라,
나눠 받으면 조각마다 다른 결론이 오고 그걸 합치는 일이 원래 작업보다 커진다.

한 단위가 워커 하나에 너무 크면 조건이나 범위를 좁혀 나누고, 너무 작으면 합친다. 판단
기준은 **워커 하나가 결과 파일 하나를 낼 수 있는 크기**다.

## 3. 프로바이더가 codex 하나일 때

프로바이더가 둘 이상인 환경을 전제로 쓴 역할 배정표는 여기서 쓸 수 없다. codex만 활성인
환경에서는 "다른 프로바이더로 폴백"이라는 선택지가 없으므로, **codex 안에서 조회된 모델
사이에 등급을 매긴다.**

1. 활성 provider와 모델을 조회한다. 표를 믿지 않고 조회 결과로 후보를 만든다 — 플랜에 따라
   쓸 수 있는 모델이 다르고, 없는 모델을 배정하면 워커가 기동 자체를 못 한다.
2. 조회된 모델을 성능 순으로 늘어놓고 역할에 배정한다. 후보가 하나뿐이면 모든 역할이 같은
   모델을 쓴다. 그것은 실패가 아니라 이 환경의 정상 상태다.
3. 역할 사이의 차이는 모델이 아니라 **thinking 등급**으로 낸다. 모델이 하나여도 조사·수집은
   낮은 등급, 해석·검토는 높은 등급으로 가른다. thinking을 올리면 쿼터를 더 쓰므로 1절
   예산과 함께 본다.

**모델이 하나라는 이유로 역할 구분을 없애지 않는다.** 역할은 워커에게 무엇을 시키고 무엇을
시키지 않을지의 경계이기도 해서, 같은 모델이어도 브리핑이 달라진다.

## 4. 연구 산출물의 합격 기준

워커 브리핑의 합격 기준 칸에 **이번 작업에 해당하는 것만** 골라 원문으로 싣는다. 해당하지
않는 항목까지 전부 실으면 워커가 무엇이 진짜 기준인지 못 가린다.

| 항목 | 무엇을 요구하나 | 왜 |
| --- | --- | --- |
| 단위 | 모든 수치에 단위를 붙이고 단위계를 하나로 통일한다 | 단위가 섞이면 틀린 값이 그럴듯한 자릿수로 나와 검토에서도 안 걸린다 |
| 물질·에너지 수지 | 수지가 맞는지 먼저 확인한다 | 여기가 안 맞으면 뒤의 계산이 전부 틀린 값 위에 쌓여, 이후 단계를 아무리 잘해도 결과를 못 쓴다 |
| 유효숫자 | 입력의 유효숫자를 넘겨 쓰지 않는다 | 넘겨 쓰면 없는 정밀도가 있는 것처럼 보이고, 그 값을 근거로 다음 판단이 내려진다 |
| 출처 | 수치마다 어디서 왔는지 적는다 — 문헌·DB·계산·가정 중 무엇인지 | 가정으로 넣은 값과 문헌값이 섞이면 나중에 무엇을 다시 확인해야 할지 모른다 |
| 조건 명시 | 온도·압력·조성 등 그 값이 성립하는 조건을 함께 적는다 | 조건 없는 물성값은 다른 조건에 그대로 쓰이고, 쓴 사람은 그 사실을 모른다 |
| 재현 | 계산은 입력과 절차를 결과와 함께 남긴다 | 남기지 않으면 검증이 재계산이 되어 워커 하나가 더 든다 |
| 미확인 표시 | 확인하지 못한 것을 확인한 것처럼 쓰지 않고 그렇다고 적는다 | 빈칸은 눈에 띄지만 채워진 틀린 값은 안 띈다 |

**추정값을 금지하지 않는다.** 연구 초기에는 가정이 필요하다. 요구하는 것은 그것이 추정이라는
표시이고, 표시가 없는 추정값만이 문제다.

## 5. 검토

연구 산출물의 검토는 코드 리뷰와 다른 것을 본다. 코드는 돌려보면 맞는지 알지만, 연구
결과는 **그럴듯하게 틀릴 수 있고** 그 틀림이 실행으로 드러나지 않는다.

검토 워커에게 넘기는 것은 원본 합격 기준과 대상 경로다. 작성 워커의 보고나 해결 방향을
같이 넘기면 검토가 그 결론을 따라가서, 독립 검토를 둔 이유가 없어진다.

검토에서 보게 할 것:

1. 4절 기준 중 이 작업에 걸린 항목을 실제로 충족했나
2. 수치가 물리적으로 가능한 범위인가 — 음의 농도, 100%를 넘는 수율, 평형을 넘는 전환율
3. 출처가 적힌 값이 정말 그 출처에 있나 — 표본으로 몇 개를 역추적한다
4. 결론이 제시된 데이터로 뒷받침되나, 아니면 데이터 밖으로 나갔나

**검토 워커에게 결과를 고치게 하지 않는다.** 고치는 것은 작성자 몫이고, 검토가 고치기
시작하면 그 수정은 아무도 검토하지 않은 것이 된다.

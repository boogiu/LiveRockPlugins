# 실험 계획과 마일스톤

실험 목록 대신 **다음 단계로 넘어갈 근거가 있는 계획**을 만든다. 날짜와 작업만 나열하면
측정이 끝나도 연구 질문에 답했는지 판단할 수 없으므로, 각 마일스톤을 결정과 연결한다.

## 1. 연구 질문과 제약을 먼저 고정한다

이미 받은 자료에서 연구 질문, 대상 계·공정, 비교 기준, 원하는 결과, 보유 장비·시료,
기간·예산, 알려진 운전 한계를 추린다. 같은 내용을 다시 물으면 대화와 토큰만 늘어난다.

빠진 정보는 계획을 바꾸는 것만 묶어서 질문한다. 목표·비교 대상·실험 가능 범위가 없으면
확정 조건을 만들 수 없으므로, 답을 기다리는 동안 단계 구조와 미확인 목록만 작성한다.
선택이 필요한 방법은 이유와 함께 제안하고 승인 상태를 적는다. 제안이 다음 단계의
확정 전제로 흘러가면 사용자가 선택하지 않은 실험을 계획하게 된다.

### 추측 금지가 실제로 뜻하는 것

**없는 사실을 채우지 않는다.** 계획은 미래의 선택을 제안할 수 있지만, 장비 성능·물성·안전한
운전 범위·기대 결과를 아는 것처럼 쓰면 실제 실험의 근거가 틀린 값으로 바뀐다.

- 사용자 제공·문헌·계산·설계 제안·미확인을 구분하고 값마다 근거 위치를 적는다.
  출처 없는 수치는 확정값과 구별되지 않으므로, 근거가 없으면 수치를 비워 두고 미확인으로 적는다.
- 가설은 가설로, 임시 조건·횟수·임계값은 제안으로 표시한다. 가설이 이미 입증된 결과처럼
  보이거나 제안이 승인된 조건처럼 보이는 것을 막기 위해 승인 상태도 함께 적는다.
- 문헌 확인이 필요하면 literature-analysis에 필요한 질문과 조건을 넘긴다. 여기서 논문을
  찾아 읽는 절차를 복제하면 경계가 겹치고 같은 근거를 두 번 조사하게 된다.
- 관련 운전 한계가 확인되지 않으면 해당 마일스톤의 진입 조건을 미충족으로 둔다.
  일반적인 숫자를 안전 범위로 대신 쓰면 장비·물질·조건 차이를 지우게 된다.

## 2. 변인과 측정 항목을 연결한다

계획을 표로 작성하기 직전에 [계획 서식](assets/experiment-plan.md)을 읽고 채운다.
서식을 하나로 유지하면 변인·측정·판정 사이의 누락을 같은 위치에서 확인할 수 있다.
기본 결과는 대화에 제시하고, 사용자가 파일을 요청한 경우에만 지정 형식으로 저장한다.
불필요한 계획 파일을 늘리지 않기 위해 저장 형식을 임의로 추가하지 않는다.

| 구분 | 정할 내용 | 이유 |
| --- | --- | --- |
| 독립변수 | 실제 조작 항목, 단위, 수준·범위, 조작 방법 | 명목 조건과 실제 조작이 다르면 비교가 성립하지 않는다 |
| 종속변수 | 관측·계산할 응답, 정의, 단위, 산식과 필요한 원자료 | 이름만 같은 응답을 서로 다른 기준으로 비교하지 않도록 한다 |
| 통제변수 | 유지 조건과 허용 변동, 확인 방법 | 유지했다고 가정한 조건이 효과의 원인일 수 있다 |
| 교란·블록 요인 | 배치·시간·장비 등 영향 요인과 기록·배치 방안 | 처리 효과와 실험 환경 효과가 섞이지 않도록 한다 |
| 측정 항목 | 변수와의 연결, 방법·장비, 시점·빈도, 교정·검출 한계·불확도 | 효과가 측정 가능한지와 판정에 쓸 수 있는지를 확인한다 |

같은 변수도 마일스톤마다 역할이 바뀔 수 있으므로 단계별 역할을 적는다. 앞 단계의
독립변수를 뒷 단계에서 고정하는 경우 통제 조건을 누락하지 않기 위해서다.
측정 방법의 성능이 없으면 미확인으로 남기고 방법 확인 단계를 선행시킨다. 검출되지 않은
값을 효과가 없는 것으로 판단하지 않기 위해서다.

## 3. 실험을 결정 단위로 나눈다

마일스톤 하나에 답할 질문 하나와 다음 결정 하나를 연결한다. 실험 횟수나 주차만으로
나누면 무엇을 확인해야 다음 단계로 가는지 정해지지 않는다.

| 상황 | 다음 동작 | 이유 |
| --- | --- | --- |
| 측정·기준 조건이 아직 검증되지 않았다 | 측정 가능성과 기준 조건 확인을 선행 마일스톤으로 둔다 | 본 실험의 차이가 측정 오차인지 효과인지 구별해야 한다 |
| 요인 영향이나 실행 가능한 범위가 불명확하다 | 범위·요인 탐색을 제안한다 | 근거 없이 세부 조건을 확정하면 불필요한 실험이 늘어난다 |
| 비교 조건과 측정 방법이 확보됐다 | 가설 검증·조건 비교를 설계한다 | 확보된 근거가 있으면 불필요한 탐색을 반복할 필요가 없다 |
| 최종 후보나 결론이 정해졌다 | 독립 반복·별도 조건 확인의 필요성을 판단한다 | 선정에 사용한 자료만으로 재현성을 주장하지 않도록 한다 |

모든 상황에 같은 단계 수를 강제하지 않고 필요한 마일스톤만 남긴다. 반응·분리·재료·공정
실험은 준비 상태가 다르므로, 불필요한 단계는 비용만 늘린다.
각 단계에 선행 마일스톤, 진입 조건, 조건 조합, 비교군, 반복 단위·횟수, 실행 순서,
소요 자원·기간 근거, 산출물, 판정과 후속 동작을 적는다. 앞 결과에 의존하는 조건과
일정은 조건부로 표시한다. 아직 얻지 않은 결과로 뒤의 실험을 확정하지 않기 위해서다.

독립 실험 반복과 같은 시료의 반복 측정을 구분한다. 반복 측정 수를 표본 수로 세면
불확도를 과소평가한다. 반복 횟수는 기존 변동·검출할 차이·자원에 근거해 정하고,
근거가 없으면 예비 측정으로 산정하는 경로를 제안한다.
랜덤화·블록화·상호작용 검토는 적용 가능성과 연구 질문에 따라 선택한다. 요인을 하나씩
바꾸는 방식만 강제하면 상호작용을 놓치며, 운전 제약을 무시한 순서는 실행할 수 없다.
총 실행 수는 조건 조합·독립 반복·비교군의 중복 여부를 확인해 계산하고 산식을 남긴다.
중복 계수와 숨은 비용을 막기 위해 준비·측정 시간도 실험 운전 시간과 구분한다.

## 4. 판정 기준을 실험 전에 정한다

통과·재시험·중단 기준에 지표, 단위, 비교 대상, 임계값의 근거, 판정 방법과 다음 동작을
붙인다. 결과를 본 뒤 기준을 바꾸면 원하는 결론에 맞춰 실험을 평가하게 된다.
임계값을 정할 근거가 없으면 미확인으로 남기고 합의 또는 예비 측정을 선행 조건으로 둔다.
통과 여부를 계산할 수 없는 단계는 실행 준비가 끝났다고 보고하지 않는다.

효과 판정과 측정 품질 판정을 구분한다. 측정 품질이 불충분한 결과는 가설 실패로 처리하지
않고, 원인 확인·재시험 경로를 적는다. 재시험의 범위·횟수·중단 조건도 근거 또는 제안으로
남긴다. 기준 없는 반복은 비용을 소모하면서 결론을 선택하게 만들 수 있다.
물질·에너지 수지나 정규화가 응답 정의에 필요한 경우 입력·단위·계산 기준을 확인한다.
해당하지 않는 실험에 수지 검증을 강제하지 않는다. 필요한 계산만 검증해야 비용을 아끼며
응답의 분모나 시스템 경계 오류를 잡을 수 있다.

## 5. 쿼터와 워커 연결

보통은 단일 에이전트가 전체 계획을 작성한다. 마일스톤마다 워커를 띄우면 앞 단계 결과를
기다리거나 서로 다른 전제로 초안을 써서, 합치는 비용이 계획 비용보다 커진다.

독립된 조건 자료나 계산 확인을 나눌 필요가 있을 때만 research-orchestration에 연결한다.
1절로 총 워커 수·동시 실행 예산을 먼저 정하고, 제한 플랜에서는 순차 실행부터 검토한다.
2절에 따라 서로 결과를 필요로 하지 않는 조건 세트·자료 묶음으로 나누며, 전체 해석과
계획 초안 작성은 나누지 않는다. 4절의 단위·출처·조건·재현·미확인 표시와 해당하는 수지·
유효숫자 기준만 브리핑에 넣는다. 독립 작업만 나누고 적용 기준만 보내야 토큰을 아낄 수 있다.
워커 기동은 agent-orchestration에 맡기고, 이미 워커로 받은 작업이면 재위임하지 않는다.
실행 수단이 없으면 직접 계획을 계속하고 자료 확인의 미실행을 적는다. 기동되지 않은
작업을 완료된 근거로 쓰지 않기 위해서다.

## 6. 제출 전에 연결을 검사한다

모든 독립변수에 수준·단위·조작 방법 또는 미확인 표시가 있는지, 모든 응답에 측정 항목이
연결되는지, 모든 판정 지표가 실제 측정 또는 재현 가능한 계산으로 얻어지는지 확인한다.
누락은 변인 표에서 판정까지 전파되므로 한 표만 확인해서는 충분하지 않다.
선행 관계가 순환하지 않는지, 자원·기간과 총 실행 수가 맞는지 확인한다. 실행할 수 없는
순서나 비용을 계획 완료로 내놓지 않기 위해서다.
마지막에는 확정·제안·미확인을 요약하고 사용자에게 필요한 결정만 남긴다. 미확인 항목이
없으면 없음으로 적어, 확인을 마친 것인지 확인 항목을 빠뜨린 것인지 구별한다.
